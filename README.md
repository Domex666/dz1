# Notes API — заметки с тегами

Мини-API на PHP 8.4 без фреймворка: CRUD по заметкам, фильтрация по тегам
и аналитика по частоте тегов. Хранилище — один JSON-файл, базы данных нет.

Домашнее задание после занятия 1. Оценивается не размер продукта, а пройденный цикл:
контекст → спецификация → наивный прогон → работа по спеке → проверка → отчёт.
Исходный текст задания — в `homework.pdf`, инструкция курса сохранена
в `docs/course-readme.md`.

> **Статус: финальная версия, работа завершена.** Все пункты обязательной части
> закрыты, включая независимый аудит. Что осталось за рамками и почему — в разделах
> «Что не сделано и что упрощено» ниже и в `sessions/STATE.md`.

## Запуск

Нужен PHP 8.4. Зависимостей нет — ни Composer, ни `vendor/`, ставить нечего.

```bash
php -S 0.0.0.0:8080 -t public public/index.php
```

Второй аргумент `public/index.php` — роутер-скрипт. Без него встроенный сервер PHP
отвечает 404 на путях, которым не соответствует файл на диске.

Проверка, что поднялось:

```bash
curl http://localhost:8080/api/v1/notes
# {"success":true,"data":{"items":[]}}
```

Ниже 8.4 не соберётся: в контракте исключений используются property hooks.

### Тесты

```bash
php tools/phpunit.phar --colors=never
```

### Ручная проверка живого сервиса

```bash
sh scripts/smoke.sh          # 22 сценария, включая нештатные
```

Скрипт сбрасывает `storage/notes.json` в пустое состояние перед прогоном.

### Если PHP не установлен

Любую команду выше можно выполнить в контейнере, не ставя PHP на машину:

```bash
# сервис
docker run --rm -p 8080:8080 -v "$PWD":/app -w /app php:8.4-cli \
  php -S 0.0.0.0:8080 -t public public/index.php

# тесты
docker run --rm -v "$PWD":/app -w /app php:8.4-cli php tools/phpunit.phar --colors=never
```

Это просто способ вызвать `php` — замена `brew install php`, а не часть проекта.
В репозитории нет ни `Dockerfile`, ни `docker-compose.yml`; код о контейнере не знает,
и убрать его из процесса можно не тронув ни строки. Хранилище остаётся JSON-файлом,
базы данных, кэша, очередей и внешних сервисов нет.

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/v1/notes` | Создать заметку |
| `GET` | `/api/v1/notes` | Список, фильтр `?tags=a,b&mode=all\|any` |
| `GET` | `/api/v1/notes/{id}` | Одна заметка |
| `PUT` | `/api/v1/notes/{id}` | Полная замена, идемпотентно |
| `DELETE` | `/api/v1/notes/{id}` | Удалить |
| `GET` | `/api/v1/tags/top` | Топ тегов, `?limit=1..100` |

Полный контракт со схемами, кодами ошибок и поведением на границах — в `SPEC.md`.

## Что сделано

- Шесть эндпоинтов, единый формат успеха и ошибки, трассировки стека наружу не уходят.
- Нормализация тегов: `trim` + верхний регистр + дедупликация после нормализации.
  `["  Работа ", "работа", "Work"]` → `["РАБОТА", "WORK"]`.
- Неизвестное поле в теле — `422` с именем поля, а не молчаливое игнорирование.
- `PUT` идемпотентен: повторная отправка того же тела не двигает `updatedAt`.
- Повторный `DELETE` — `404`.
- Три состояния файла-хранилища разведены: нет / пустой / испорчен.
  Испорченный файл не чинится и не перезаписывается — `500 STORAGE_CORRUPTED`.
- Атомарная запись через временный файл и `rename`, блокировка через `flock`.
- PHP-предупреждения перехватываются и не попадают в тело ответа: без этого отказ прав
  на файл печатал абсолютный путь и ломал статус на `200 OK` с `text/html`.
- 90 тестов, 227 проверок: 73 фича-теста на эндпоинты и 17 юнит-тестов на нормализацию,
  блокировку и рендер ошибок. Тесты не ходят в сеть и пишут только во временный каталог.
- Архитектура по плагину `laravel-arch`: слои, контракты, DTO, исключения со своим
  HTTP-кодом. Laravel не используется.

## Что не сделано и что упрощено

Честно и по пунктам.

- **Наивный прогон сделан в той же сессии**, где уже обсуждалась спецификация, а не
  до неё. Изоляция слабее, чем требовалось; подробности в `naive/README.md`.
  Разница между прогонами в реальности скорее больше показанной, а не меньше.
- **Конкурентность не нагружалась.** Аудит показал на 60 параллельных запросах,
  что блокировка работает, но в наборе тестов проверяется только сам факт её удержания,
  а не поведение под нагрузкой.
- **Замена атомарной записи на прямую не ловится тестом.** Мутация «`rename` → прямой
  `file_put_contents`» остаётся неубитой: воспроизвести оборванную запись в тесте
  не получилось. Единственная известная непокрытая мутация.
- **Часть находок аудита отклонена осознанно** — список с причинами
  в `sessions/session-2.md`.
- **Пагинации нет.** Список отдаётся целиком. На сотне заметок это незаметно,
  на десяти тысячах — проблема.
- **Блокировка берётся на файл целиком.** Любая запись сериализует все остальные.
  Для учебного сервиса достаточно, под нагрузкой это узкое место.
- **Аутентификации нет**, заметки общие.
- **Границы длин** (тег 32, тегов 10, `title` 200, `content` 10000) выбраны агентом
  как допущение и человеком не подтверждены.
- **Полнотекстового поиска, категорий тегов, мягкого удаления и OpenAPI нет** —
  сознательные нецели, список в `SPEC.md`.
- **Конкурентная запись проверена только логикой `flock`**, нагрузочного теста нет.

## Сравнение двух прогонов

Наивный прогон лежит в `naive/index.php` — 90 строк в одном файле, получен одним
коротким промптом без спеки и правил. Итоговый вариант — 42 файла по слоям.
Разница не в объёме кода, а в том, какие решения были приняты молча.

| Что | Наивный прогон | После спецификации |
|---|---|---|
| Нормализация тегов | Нет. `Работа` и `работа` — разные теги | `trim` + верхний регистр + дедуп, правило записано в спеке до кода |
| Пустой тег `"   "` | Сохраняется как есть | `422` с индексом `tags.0` |
| Лишнее поле в теле | Молча игнорируется | `422` с именем поля |
| Фильтр по нескольким тегам | Только OR, без выбора | `mode=all` по умолчанию, `mode=any` явно |
| Повторный `PUT` тем же телом | `updated_at` меняется каждый раз | Идемпотентно, `updatedAt` не двигается |
| Повторный `DELETE` | `200 {"ok":true}` — врёт об успехе | `404` |
| `id` | Автоинкремент `count($notes) + 1` — после удаления выдаёт занятый id | UUID v4 |
| Формат ошибки | Три разных: `{"error":"..."}`, отсутствие тела, текст | Единый: `code`, `message`, `fields` |
| Коды ответов | Только 201, 404 и 400 | 200, 201, 204, 400, 404, 405, 422, 500 |
| Испорченный файл | `?: []` — молча считает хранилище пустым и **затирает данные** первой же записью | `500 STORAGE_CORRUPTED`, запись отказывает, файл не тронут |
| Пустой файл | Работает случайно, через тот же `?: []` | Разведён явно как штатное состояние |
| Запись | `file_put_contents` — оборванная запись бьёт файл | Временный файл + `rename` |
| Конкурентность | Нет | `flock` на время операции |
| Топ тегов | `arsort`, при равенстве порядок произвольный | Тай-брейк по алфавиту, порядок воспроизводим |
| `limit` | Захардкожен 10 | Параметр `1..100`, вне границ — `422` |
| Тесты | Нет | 50 |

Где наивный оказался лучше: он был готов за один промпт и полностью помещается
на один экран. Для одноразового скрипта это правильный размер, и раскладывать
его по слоям было бы вредно. Разница начинает окупаться там, где у поведения
появляются границы и их надо удерживать.

Главная находка не в списке отличий, а в его характере: наивный вариант не «не успел»
принять эти решения — он принял их все, просто молча и не там, где их видно.

## Независимый аудит

Проведён тремя агентами в чистом контексте, без истории обсуждения проекта:
контракт против кода, правила и архитектура, качество тестов. Аудиторам было
запрещено править код — иначе находка исчезает вместе с багом.

Главный результат — не список дефектов, а мутационная проверка: **из 16 мутаций,
внесённых в рабочий код, 12 не уронили ни одного из 50 тестов**. То есть три четверти
набора ничего не доказывали. Самое неприятное: удаление `flock` теряло 6 записей
из 60 параллельных запросов, и тесты оставались зелёными; а оба теста «трассировка
не уходит наружу» проходили тавтологически, потому что били по телам, которые
трассировку не могли бы содержать ни при какой реализации.

После правок все восемь перепроверенных мутаций убиты, набор вырос с 50 до 90 тестов.

Полный разбор — какие находки приняты, какие отклонены и почему — в `sessions/session-2.md`.
