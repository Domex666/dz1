# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-17 · Сессия 1 · Docker образ `php:8.4-cli` (PHP 8.4.24)

- **Тип:** контейнер / рантайм
- **Установка:** отдельной команды нет, образ тянется при первом запуске:
  `docker run --rm -v "$PWD":/app -w /app php:8.4-cli php -v`
- **Зачем:** PHP и Composer в системе отсутствуют, локальную установку владелец проекта
  запретил. Контейнер нужен как рантайм для линта, тестов и запуска сервиса
- **Область:** проект
- **Отступление:** задание запрещает Docker. Отступление осознанное, границы описаны
  в `SPEC.md`: один контейнер, только PHP, без базы, кэша и внешних сервисов
- **Почему именно 8.4, а не 8.5:** на 8.4 написан эталон плагина `laravel-arch`;
  property hooks в `ResponseExceptionInterface` работают без переписывания на геттеры.
  В контейнере выбор версии бесплатный, поэтому взята та, что совпадает с эталоном
- **Проверка:** `php -v` → PHP 8.4.24; `php -l` прошёл по всем 42 файлам проекта

## 2026-08-17 · Сессия 1 · PHPUnit 11.5.56 (phar)

- **Тип:** библиотека / CLI
- **Установка:** `curl -sSL -o tools/phpunit.phar https://phar.phpunit.de/phpunit-11.phar`
- **Зачем:** фича-тесты на эндпоинты — прямое требование владельца проекта
- **Область:** проект, файл лежит в репозитории
- **Почему phar, а не Composer:** Composer тянет за собой `vendor/`, `composer.json`
  и целое дерево зависимостей ради одного инструмента. Один файл проще и делает
  сдачу воспроизводимой без установки чего-либо
- **Проверка:** `php tools/phpunit.phar --version` → PHPUnit 11.5.56;
  прогон 50 тестов, вывод в `docs/evidence/phpunit.log`
